# download-speed-test

[![tests](https://github.com/fry-alt/download-speed-test/actions/workflows/tests.yml/badge.svg)](https://github.com/fry-alt/download-speed-test/actions/workflows/tests.yml)

Консольный скрипт на Python для замера скорости скачивания. Он делает 10
запросов к указанному адресу по очереди, каждый раз дожидается полного ответа
и печатает:

- среднее время запроса;
- общий объём скачанных данных;
- скорость скачивания в **Мбит/с**.

Нужна только стандартная библиотека Python, ставить ничего не надо.

## Требования

Python 3.9 или новее. Проверить версию:

```bash
python3 --version
```

## Запуск

```bash
git clone https://github.com/fry-alt/download-speed-test.git
cd download-speed-test
python3 speedtest.py <адрес>
```

Пример с тяжёлой картинкой (14.7 МБ) из Википедии:

```bash
python3 speedtest.py https://upload.wikimedia.org/wikipedia/commons/3/3f/Fronalpstock_big.jpg
```

Если не указать `https://`, скрипт добавит его сам.

### Параметры

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `url` | — | адрес, который скачиваем (обязательный) |
| `-n`, `--requests` | `10` | сколько запросов сделать |
| `-t`, `--timeout` | `30` | сколько секунд ждать данных от сервера, потом ошибка |
| `-h`, `--help` | | справка |

```bash
python3 speedtest.py https://proof.ovh.net/files/10Mb.dat -n 5 -t 10
```

## Единицы измерения

**Основная единица скорости: Мбит/с (мегабиты в секунду).** В ней указывают
скорость провайдеры и сервисы вроде speedtest.net, поэтому результат можно
сразу с ними сравнить. В скобках для удобства выводятся МБ/с (мегабайты в
секунду), их проще сопоставить с размером файла.

Все приставки десятичные, как у провайдеров:

- 1 Мбит = 1 000 000 бит;
- 1 МБ = 1 000 000 байт (не 1 048 576);
- 1 байт = 8 бит, поэтому 1 МБ/с = 8 Мбит/с.

Время выводится в секундах, объём в Б / КБ / МБ / ГБ, а в скобках ещё и точное
число байт.

## Как считается

Для каждого запроса скрипт засекает время от начала запроса до получения
последнего байта ответа (таймер `time.perf_counter()`) и считает, сколько байт
тела ответа пришло.

```
среднее время запроса = сумма времён / число запросов
общий объём           = сумма байт по всем запросам
скорость, Мбит/с      = общий объём × 8 / общее время / 1 000 000
```

Скорость считается как **весь объём, делённый на всё время**, а не как
среднее от скоростей отдельных запросов. Иначе запрос, который случайно
прошёл за секунду, весил бы в итоге столько же, сколько запрос на полминуты,
и результат завышался бы.

Чтобы замер был честным, скрипт:

- читает ответ до конца кусками по 64 КБ, так что весь файл не держится в памяти;
- считает реально полученные байты и сверяет их с заголовком `Content-Length`;
  если соединение оборвалось раньше, это ошибка, а не «быстрый» запрос;
- шлёт `Cache-Control: no-cache`, чтобы CDN и прокси не отдавали копию из кэша;
- шлёт `Accept-Encoding: identity`, чтобы сервер не сжимал ответ и мы мерили
  настоящий размер файла;
- идёт по редиректам (301/302) к итоговому файлу.

## Ошибки

Если запрос не удался (HTTP 4xx/5xx, нет сети, неверный адрес, таймаут,
оборванный ответ), скрипт останавливается и пишет понятную причину:

```
[ 1/10] ошибка
Ошибка на запросе 1/10: сервер ответил HTTP 404 Not Found
```

Коды выхода: `0` замер прошёл, `1` ошибка во время запроса, `2` неверные
аргументы или адрес, `130` прервано через Ctrl+C.

## Ограничения

- **В каждый запрос входит установка соединения** (DNS, TCP, TLS). Каждый
  запрос открывает новое соединение, так что это честное «время запроса».
  Но на маленьких файлах оно занимает большую часть времени и занижает
  скорость, поэтому, если в среднем файл меньше 1 МБ, скрипт предупреждает
  об этом. Для замера берите файлы от 10 МБ.
- Запросы идут в один поток, поэтому быстрый канал (сотни Мбит/с и выше) один
  поток может не загрузить полностью, и скорость получится ниже реальной.
- Результат зависит от сервера: если он медленный, скрипт покажет скорость
  сервера, а не вашего канала.
- Некоторые сервисы ограничивают частоту запросов. Например,
  `speed.cloudflare.com` может ответить `HTTP 429 Too Many Requests`.

## Тесты

Тесты поднимают локальный HTTP-сервер, интернет для них не нужен:

```bash
python3 -m unittest -v
```

Что проверяется: тело ответа читается целиком, запросов ровно N и они идут
строго по очереди (сервер считает, сколько запросов было одновременно),
отправляются заголовки против кэша, обрабатываются редиректы, ответы без
`Content-Length`, оборванные и пустые ответы, ошибки HTTP, таймаут, отказ в
соединении, неверные аргументы, а также формулы и форматирование единиц.
